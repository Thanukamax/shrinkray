**Best (lowest ratio — codec floor):**

1. `synthetic/constant_red`        — ratio = 0.000078

4. `synthetic/smooth_linear_x`     — ratio = 0.000078
5. `synthetic/stripes_v`           — ratio = 0.000239

These are the bilinear predictor's "perfect prediction → residual ≈ all zeros → zstd crushes" floor. The ~78 ppm overhead is bitstream framing + low-mip hash + headers.

**Worst (highest ratio — codec ceiling):**

1. `pbr-cc0/Wood062_NormalGL`      — ratio = 0.792
2. `synthetic/highfreq_noise_2`    — ratio = 0.949
3. `synthetic/highfreq_noise_3`    — ratio = 0.964
4. `synthetic/highfreq_noise_1`    — ratio = 0.985
5. `synthetic/highfreq_noise_0`    — ratio = **1.064** ← codec lost to ExactBackup

Pure xorshift noise has no exploitable structure, so the residual is the original minus a smoothed copy of itself — essentially still i.i.d. random. zstd-19 can't compress random bytes, and the int16 doubling means the residual is *bigger* than the source. This is the paper's honest worst case.

## 3 surprising findings (what I actually observed)

1. **Synthetic value-noise (octaves 1-8) lands at 0.10 — close to PBR-roughness.** I expected octaves 6-8 to climb toward 0.5+; they cap at 0.13. The smoothstep interpolation in the synthetic generator keeps gradients soft enough that bilinear prediction stays effective even at 32×32 lattice cells. **Implication for the paper:** synthetic-noise content is *not* a stand-in for "high-frequency game texture" — real PBR-color (median 0.39) is 4× harder.

2. **BC3 beats pixel on real PBR-normal (0.58 vs 0.69) but the adaptive probe doesn't flip.** HP energy on `Wood062_NormalGL` and the other 5 normal maps comes in below the 25 threshold (typical 5-15) because pixel-space neighbour differences average down on noisy normals. The codec-space probe is mis-calibrated for the BC5/BC3 normal-map case — it's looking at pixel-space high-frequency energy and missing the fact that BC quantization absorbs the prediction error structurally. **Concrete follow-up:** add a BC5-specific routing rule, or train the probe against a held-out PBR set instead of the synthetic samples it was tuned on.

3. **highfreq_noise_0 crosses ratio = 1.0 (1.064×).** This is the codec losing to ExactBackup. The bench correctly reports it — no silent failure — but it's the first time we've quantified the loss: ~6 % overhead on truly incompressible content. The good news: the adaptive probe correctly routes the noise samples to BC3-byte (0.71 vs 1.06 pixel), so the deployed codec never actually ships the 1.06 row. The bad news: even BC3-byte costs 70 % of the BC baseline on pure random noise, so any uniformly random texture in a real game (rare, but exists — procedural detail layers) will be a near-zero-savings case.

## What ESRGAN will likely change (testable when agent-A2 lands)

When `EsrganX4Predictor` replaces `BilinearPredictor`, the residual = `top - predictor(low)`. ESRGAN should reduce the residual *most* on content where bilinear's failure mode is "blur, miss edges". Three hypotheses with falsifiable predictions:

1. **PBR-color median drops from 0.39 → ~0.20-0.25.** ESRGAN hallucinates plausible high-frequency detail from low-mip color, and PBR diffuse maps mostly match the ESRGAN training distribution (natural surfaces). If this holds, the headline ratio for the paper is "AI-restore at <0.25× ExactBackup, byte-exact via residual."

2. **pbr-normal stays ~0.6× pixel, or *increases*.** ESRGAN is trained on natural images, not normal maps. The G-channel up-and-down ordering on normal-maps confuses standard ESRGAN models; the residual will be larger than bilinear's. **Counter-intuitive prediction: ESRGAN makes the normal-map case worse.** If true, the paper's adaptive selector needs a `predictor_id` axis too: bilinear for normal-maps, ESRGAN for color/diffuse.

3. **highfreq noise stays at ~1.0 regardless of predictor.** No predictor can predict random noise from a smoothed copy; the information-theoretic floor is the source entropy. This is the paper's "the codec respects Shannon" result — important for the honesty section.

## Reproducing

```bash
# Generate corpora (idempotent)
bash scripts/fetch-pbr-corpus.sh
cargo run -p shrinkray-core --release --example gen_synthetic_corpus

# Run the bench
cargo build -p shrinkray-core --release --example bench_real_content
./target/release/examples/bench_real_content \
    --corpus paper/corpus \
    --quant-steps 1,2,4 \
    --bc-formats Bc1,Bc3,Bc5,Bc7 \
    --out-csv paper/results/bench-$(date +%Y%m%d-%H%M%S).csv
```

Runtime on a 12-thread laptop: ~3 minutes for 51 images, 357 rows.
